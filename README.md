## 🎯 Описание

YogaDailyBot помогает пользователям практиковать регулярно: в режиме Daily бот присылает практики по расписанию, а в режиме By mood подбирает практику по текущему запросу пользователя. Бот работает через Telegram long polling, хранит данные в PostgreSQL и деплоится в Railway.

## 🚀 Возможности

- ✅ **Daily режим** - ежедневная отправка практик в выбранное время
- ✅ **Challenge (поток)** - общий календарный челлендж на 28 дней: запись `/flow_add`, практики по дню потока
- ✅ **By mood режим** - подбор практики по настроению/запросу без расписания
- ✅ **Сводки и расписание в группе** - итоги в 10:10 МСК; воскресенье 20:00 — расписание на неделю; день 29 — финал + автовыход в личку
- ✅ **Единый интерфейс** - быстрые фильтры доступны одновременно с настройкой времени и паузы рассылки; названия режимов сохраняются только как технические состояния в БД
- ✅ **Прогресс** - отслеживание выполненных практик
- ✅ **Избранное** - сохранение понравившихся практик и просмотр списка через `/favorite` (карусель)
- ✅ **Админ-рассылки** - массовые сообщения пользователям
- ✅ **Метки источников** - откуда пришёл пользователь при первом входе (`?start=` в ссылке на бота)
- ✅ **Railway Postgres** - рабочая база данных в Railway

## 🚀 Production Deploy: Railway

Production окружение живёт в Railway:

- service `YogaDailyBot` собирается из корневого `Dockerfile`;
- service `Postgres` хранит рабочую БД;
- бот работает через long polling, публичный webhook URL не нужен.



### Railway Variables

В `Railway -> YogaDailyBot -> Variables` должны быть заданы:

```env
BOT_TOKEN=<production Telegram bot token>
DEFAULT_TZ=Europe/Moscow
LOG_LEVEL=INFO

POSTGRESQL_HOST=<Railway Postgres public/internal host>
POSTGRESQL_PORT=<Railway Postgres port>
POSTGRESQL_USER=<Railway Postgres user>
POSTGRESQL_PASSWORD=<Railway Postgres password>
POSTGRESQL_DBNAME=<Railway Postgres database>
POSTGRES_SSLMODE=require

# ID группового чата для утренних итогов челленджа (обязательно для сводок в проде)
CHALLENGE_GROUP_CHAT_ID=<telegram_group_chat_id>

# Календарный поток (перед стартом нового челленджа; см. памятку запуска)
CHALLENGE_START_DATE=<YYYY-MM-DD понедельник старта, МСК>
CHALLENGE_START_PRACTICE_ID=<id первой практики потока>
```

Памятка «что сделать перед каждым новым потоком»: `[app/challenge/запуск-нового-потока-челленджа.md](app/challenge/запуск-нового-потока-челленджа.md)`.

### Как выкатывается production

1. Изменения попадают в ветку `main`.
2. Railway автоматически запускает новый deploy.
3. Проверяем `Deploy Logs`: должно быть `Application started`, без `Traceback`/`ERROR`.
4. Делаем smoke-test в Telegram: `/start`, принятие соглашения, пропуск или сохранение времени, быстрые фильтры и раздел расписания.



## 📬 Ежедневная рассылка практик (as is)

Сейчас в production планировщик каждую минуту запускает `send_daily_practice`, а кандидаты на отправку выбираются через `get_users_pending_for_today`. Ниже зафиксирована текущая логика как есть (без изменений и оптимизаций), чтобы безопасно пройти период челленджа.

```mermaid
flowchart TD
    START([Каждую минуту: send_daily_practice]) --> NOW[Текущее время HH:MM<br/>таймзона Europe/Moscow]
    NOW --> DB[(get_users_pending_for_today)]

    DB --> F1{is_blocked = false?}
    F1 -->|нет| SKIP[Не в выборке]
    F1 -->|да| F2{is_paused = false?}
    F2 -->|нет| SKIP
    F2 -->|да| F3{onboarding_required = false?}
    F3 -->|нет| SKIP
    F3 -->|да| F4{bot_mode in daily, challenge?}
    F4 -->|нет| SKIP
    F4 -->|да| F5{daily_schedule_enabled = true?}
    F5 -->|нет| SKIP
    F5 -->|да| F6{Сегодня уже есть practice_logs<br/>day_number >= 1?}
    F6 -->|да| SKIP
    F6 -->|нет| F7{notify_time <= сейчас?}
    F7 -->|нет| SKIP
    F7 -->|да| F8{Уже были рассылки<br/>day_number >= 1?}

    F8 -->|да| LIST[В списке на отправку]
    F8 -->|нет, новичок| F9{День настройки времени прошёл?<br/>updated_at раньше сегодня}
    F9 -->|нет, тот же день| SKIP
    F9 -->|да| LIST

    LIST --> LOOP{Для каждого user_id, chat_id}
    LOOP --> SEND[send_practice_to_user]

    SEND --> BTN[Снять «✅ Я сделал!» с прошлого сообщения<br/>кнопка избранного остаётся]
    BTN --> MODE{challenge_start_id задан?}
    MODE -->|да| CH[Практика челленджа:<br/>день = календарный день потока<br/>start_id + cohort_day]
    MODE -->|нет| DAILY[Практика Daily<br/>день недели + program_position + 1]
    CH --> FOUND{Практика найдена?}
    DAILY --> FOUND
    FOUND -->|нет| ERR[Лог ошибки]
    FOUND -->|да| TG[Сообщение в Telegram + кнопки<br/>«🧡 В избранное» и «✅ Я сделал!»]
    TG --> OK{Успех отправки?}
    OK -->|ошибка «bot was blocked»| BLOCK[is_blocked = true<br/>+ событие my_chat_member]
    OK -->|другая ошибка| ERR
    OK -->|да| INC[Инкремент счётчиков + practice_logs<br/>в challenge: challenge_day = день потока]
    INC --> BONUS{Есть бонусные практики?}
    BONUS -->|да| BONUSSEND[Отправить бонусы]
    BONUS -->|нет| LOOP
    BONUSSEND --> LOOP

    SKIP --> END([Конец минутного цикла])
    ERR --> LOOP
    BLOCK --> LOOP
```





## 📊 Структура базы данных



### Таблица `users`

Идентификация и контакты

- `user_id` - ID пользователя в Telegram (PRIMARY KEY)
- `chat_id` - ID чата
- `user_name` - имя пользователя
- `user_nickname` - username пользователя
- `traffic_source` - метка источника первого входа (`?start=`), NULL если неизвестен

Режим и расписание

- `bot_mode` - текущий режим: `pending` (не выбран), `daily`, `by_mood`, `challenge`
- `daily_schedule_enabled` - включена ли ежедневная рассылка
- `notify_time` - время уведомлений в Daily/Challenge (HH:MM)
- `onboarding_required` - нужно ли пройти онбординг (после /start и при смене режима)
- `challenge_start_id` - стартовая практика потока (из `CHALLENGE_START_PRACTICE_ID`; NULL, если не в челлендже)
- `challenge_day` - день потока у пользователя (при календарном режиме синхронизируется с днём от `CHALLENGE_START_DATE` при рассылке)

Прогресс

- `total_practices` - всего отправлено практик во всех режимах (M в «N из M»)
- `program_position` - техническая позиция в Daily-программе
- `last_practice_message_id` - id последнего сообщения с практикой (для снятия «✅ Я сделал!» при новой отправке)
- `last_practice_id` - id практики в этом сообщении (чтобы оставить кнопку избранного на старой карточке)
- `last_practice_catalog` - каталог этой практики (`yoga` / mood; для кнопки избранного на старом сообщении)
- `extra_practices_inline_messages` - JSONB-список сообщений «Еще практики» (снимаются при смене режима)

Пауза Daily-рассылки

- `is_paused` - сейчас ли на паузе
- `paused_at` - когда поставил паузу (для логики «первое напоминание через 7 дней»)
- `last_pause_reminder_at` - время последнего pause-напоминания
- `pause_reminder_step` - индекс ротации фраз pause-напоминаний

Неактивность в By mood

- `last_by_mood_active_at` - последняя активность в By mood (активация режима или отправка практики)
- `last_by_mood_reminder_at` - время последнего By mood-напоминания
- `by_mood_reminder_step` - индекс ротации фраз By mood-напоминаний

Технические

- `is_blocked` - заблокировал ли пользователь бота (событие Telegram my_chat_member и/или ошибка отправки «bot was blocked by the user»)
- `created_at` - дата регистрации
- `updated_at` - дата последнего обновления



### Таблица `yoga_practices`

- `practices_id` - уникальный ID практики
- `title` - название видео
- `video_url` - ссылка на YouTube
- `time_practices` - длительность в минутах
- `channel_name` - название канала
- `description` - описание видео
- `my_description` - дополнительное описание
- `difficulty` - сложность (легкая/средняя/высокая)
- `weekday` - день недели (1-7, NULL для любого дня)
- `created_at` - дата добавления
- `updated_at` - дата последнего обновления



### Таблица `practice_logs`

- `log_id` - уникальный ID лога
- `user_id` - ID пользователя
- `practice_id` - ID практики
- `sent_at` - время отправки
- `day_number` - номер отправки в общем счётчике (`total_practices`), для By mood используется служебное значение `-1`
- `completed_at` - дата отметки выполнения



### Таблица `by_mood_seen`

- `user_id` - ID пользователя
- `filter_key` - выбранный фильтр By mood
- `practice_id` - отправленная практика
- `sent_at` - дата отправки



### Таблица `user_favorites`

Личный список сохранённых практик пользователя.

- `user_id` - ID пользователя
- `practice_id` - ID практики
- `practice_catalog` - каталог практики (сейчас `yoga`; зарезервировано для mood-практик)
- `added_at` - когда добавили в избранное (сортировка: новые первыми)

Ограничение: одна и та же практика не дублируется у пользователя (`UNIQUE` по паре user + practice + catalog).

### Таблица `system_state`

Служебные флаги бота (ключ-значение), не привязанные к конкретному пользователю.

- `key` - название настройки (PRIMARY KEY)
- `value` - значение в текстовом виде

Используется для утренних сводок челленджа:

- `challenge_summary_last_sent_date` — дата последней отправки (защита от дублей в один день)
- `challenge_summary_stopped` — `true` после финальной сводки (день 29); сбрасывается командой `/challenge_summary_reset`
- `challenge_weekly_schedule_last_sent_date` — дата последней отправки воскресного расписания
- `challenge_auto_exit_sent_on` — дата автозавершения в личку на день 29



## 🏷️ Метки источников (UTM)

Отслеживание, **откуда пришёл пользователь** при первом входе в бота.

## Как это работает

1. В посте / био / описании публикуете ссылку с меткой:
   `https://t.me/YogaDailyBot?start=метка`
2. Человек нажимает Start.
3. Бот один раз сохраняет метку в `users.traffic_source` (первый вход).
4. Повторный `/start` или сброс онбординга метку **не меняют**.

Метка есть **только** если человек перешёл по ссылке с `?start=...`.  
Поиск бота по названию, `@username` без параметра или ссылка без `?start=` → `traffic_source` пустой (источник неизвестен).

## Правила имени метки

- Латиница, цифры, `_` или `-`
- Длина до 64 символов
- Рекомендуемый шаблон: `{канал}_{место}` или `{канал}_{место}_{кампания}`

Готовые ссылки для @YogaDailyBot (YouTube / Instagram — сюда и ставьте):

| Где публикуете | Метка | Ссылка |
|----------------|--------|--------|
| YouTube — описание / закреп | `youtube_desc` | `https://t.me/YogaDailyBot?start=youtube_desc` |
| YouTube Shorts | `youtube_shorts` | `https://t.me/YogaDailyBot?start=youtube_shorts` |
| Instagram — био | `ig_bio` | `https://t.me/YogaDailyBot?start=ig_bio` |
| Instagram — сторис | `ig_story` | `https://t.me/YogaDailyBot?start=ig_story` |
| Instagram Reels | `ig_reels` | `https://t.me/YogaDailyBot?start=ig_reels` |

## Как ставить по площадкам
YouTube
В описание: «Бот с практиками → [https://t.me/YogaDailyBot?start=youtube_desc»](https://t.me/YogaDailyBot?start=youtube_desc»).
Для Shorts — отдельная ссылка с youtube_shorts, иначе Shorts и длинные видео смешаются в отчёте.

Instagram
В обычном посте ленты ссылка не кликабельна — только текст «ссылка в био».
Чтобы отличать: в био держите ig_bio, а в сторис/рилс — свои метки; в тексте рилса пишите «ссылка в био» (люди всё равно попадут как ig_bio, если кликнут био).
Идеально для рилсов/сторис: стикер со ссылкой ig_story / ig_reels.

Telegram
В обычных сообщениях можно просто тегать `@YogaDailyBot` — так удобнее, метки не будет.
Если нужно отдельно померить пост в канале — кнопка или кликабельная ссылка `tg_channel` / `tg_chat`.

Если нужна кампания (разовый запуск)
Добавьте хвост, например:

[https://t.me/YogaDailyBot?start=ig_story_july28](https://t.me/YogaDailyBot?start=ig_story_july28)
[https://t.me/YogaDailyBot?start=youtube_desc_challenge](https://t.me/YogaDailyBot?start=youtube_desc_challenge)
Правило: только латиница, цифры, _ или -, до 64 символов.

## SQL для DBeaver

Сколько пользователей по каждой метке:

```sql
SELECT
    COALESCE(traffic_source, '(без метки)') AS source,
    COUNT(*) AS users_count
FROM users
GROUP BY traffic_source
ORDER BY users_count DESC;
```

Новые за период с разбивкой по источнику:

```sql
SELECT
    COALESCE(traffic_source, '(без метки)') AS source,
    COUNT(*) AS users_count
FROM users
WHERE created_at >= '2026-07-01'
  AND created_at < '2026-08-01'
GROUP BY traffic_source
ORDER BY users_count DESC;
```

Доля без метки:

```sql
SELECT
    COUNT(*) FILTER (WHERE traffic_source IS NULL) AS without_source,
    COUNT(*) FILTER (WHERE traffic_source IS NOT NULL) AS with_source,
    COUNT(*) AS total
FROM users;
```


## 🌀 Челленджи

Общий **календарный** челлендж на 28 дней: у всех один день потока (день 1 = `CHALLENGE_START_DATE`), одна стартовая практика (`CHALLENGE_START_PRACTICE_ID`). Без этих переменных запуск недоступен.

**Где настраивать env**

- **Прод:** Railway → Variables.
- **Локальный тест:** `test/.env.test` (не Railway), затем перезапуск `./test/run_test.sh`.

**Документы**

- Памятка запуска потока: `[app/challenge/запуск-нового-потока-челленджа.md](app/challenge/запуск-нового-потока-челленджа.md)`
- Полная спецификация: `[теория/challenge-cohort-spec.md](теория/challenge-cohort-spec.md)`



### Поток (календарный режим)

**Кратко по сценарию:**

1. Админ настраивает env и при необходимости делает `/challenge_summary_reset`.
2. Запись участников — в основном `/flow_add` (список уже известных боту `@ник` / `user_id`); запасной путь — `/challenge` (пока поток настроен в env).
3. Участник выбирает время рассылки → получает практики по календарю потока (в приветствии — дата старта ДД.ММ). Опоздавшие после старта: практика **сегодня** (в выбранное время или сразу, если время уже прошло).
4. В группе: сводки 10:10 МСК, расписание вс 20:00 МСК (см. [ниже](#сводки-и-расписание-в-группе)).
5. День 29: финал в группе + автозавершение в личку (результат N/28 + предложение продолжить расписание). Досрочный выход — `/challenge_off`.

```mermaid
flowchart TD
  admin["Админ /flow_add + список"]
  dbSetup["БД: challenge_start_id из env, setup"]
  dmWelcome["ЛС: приветствие + выбор времени"]
  userTime["Участник вводит время"]
  active["bot_mode=challenge, рассылка"]
  cohortDay["День потока = календарь от START_DATE"]
  day29["День 29: финал в группе"]
  autoOff["ЛС всем challenge: N/28 + предложение продолжить расписание"]

  admin --> dbSetup --> dmWelcome --> userTime --> active
  active --> cohortDay
  cohortDay --> day29 --> autoOff
```



**Запасной** `/challenge`**:** доступен, пока в env задан поток (`CHALLENGE_START_`*). Отдельного календарного окна записи нет — команда не в меню бота, только ручной запасной путь. Если поток не настроен — пользователь видит «Запись… закрыта» (без технических деталей). Админ через `/flow_add` записывает в любой момент; если env не заданы — админ видит техническое сообщение про настройки.

### Сводки и расписание в группе

Группа задаётся `CHALLENGE_GROUP_CHAT_ID`. Бот должен быть в группе и иметь право писать.

**Автоотправка** (не команды в Telegram) — фоновые задачи из `app/challenge/jobs.py`:


| Что                                                          | Когда                                                                                                                                                   | Код                                               |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Утренняя сводка (ежедневная / промежуточная / **финальная**) | каждый день **10:10 МСК**                                                                                                                               | `summary/job.py` + тексты в `summary/messages.py` |
| Расписание на неделю                                         | **вс 20:00 МСК** (в т.ч. воскресенье **перед** понедельником старта → дни 1–7). Нужны настроенный поток и группа; **активные участники не обязательны** | `week_schedule/job.py`                            |
| Автозавершение в личку                                       | день **29**, после финальной сводки (или в то же окно 10:10)                                                                                            | `flow/exit_job.py`                                |


Отдельной «команды финальной сводки» нет: в день 29 та же утренняя задача выбирает финальный текст. Админ-команды `/challenge_summary_preview` и `/challenge_schedule_preview` — только ручной прогон для теста; `/challenge_summary_reset` — сброс флагов перед новым потоком.

**Кто считается участником сводки:** пользователи с `bot_mode = challenge`, заданным `challenge_start_id`, без паузы, блокировки и незавершённого онбординга. Основной способ записи — админ `/flow_add`.

**Как считается выполнение (ежедневная сводка):** нажали «✅ Я сделал!» **вчера** (любая практика) **или** отметили практику челленджа, **отправленную вчера** — в том числе утром следующего дня, пока сегодняшняя ещё не пришла.

**Промежуточные итоги (дни 8, 15, 22):** N/M — выполнено за **все прошедшие дни, кроме сегодняшнего** (сводка в 15-й день: «10/14 дней»). Засчёт — как в ежедневной сводке.

**Типы сообщений** (по календарному дню потока):


| День челленджа           | Что в посте                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 1–6                      | Итоги за вчера: сколько и кто выполнил                                                                              |
| 8, 15, 22 (понедельники) | Промежуточный прогресс N/M (без сегодняшнего дня) + «Вы прекрасны! Продолжайте!»                                    |
| 28 (воскресенье)         | Итоги за вчера (последний день практик)                                                                             |
| 29 (понедельник)         | Финальные итоги в группе + **автозавершение в личку** всем с `bot_mode = challenge` (результат N/28 + предложение продолжить расписание) |
| После 29                 | Сводки не отправляются, пока админ не выполнит `/challenge_summary_reset`                                           |


Имена в сводке: `@nickname`, если есть; иначе `user_name`.

Если `CHALLENGE_GROUP_CHAT_ID` пустой или нет активных участников челленджа — сводка молча пропускается (на день 29 автозавершение в личку всё равно выполняется).

## 🧡 Избранное

Пользователь может сохранять понравившиеся практики и возвращаться к ним в любой момент — во всех режимах (Daily, Challenge, By mood).

Подробная спецификация: `[теория/favorites-spec.md](теория/favorites-spec.md)`.

### Как сохранить практику

Под **основной** практикой (не под бонусной) две кнопки в одном ряду:

```
[ 🧡 В избранное ]   [ ✅ Я сделал! ]
```

Если практика уже в списке — вместо «В избранное» показывается **«🧡 Убрать»**.

Кнопка есть под практиками из:

- ежедневной рассылки (Daily / Challenge);
- By mood (все фильтры, «Сам решу»);
- «Ещё практики».


| Действие | Ответ бота                               |
| -------- | ---------------------------------------- |
| Добавить | Toast: «Добавил практику в избранное 🧡» |
| Убрать   | Toast: «Удалил практику из избранного»   |




### Раздел «Избранное 🧡»

- Команда: `/favorite`
- В меню бота (слева от поля ввода): **«Избранное 🧡»** (первая в списке)

**Пустой список:** подсказка добавить практику кнопкой «🧡 В избранное» под сообщением.

**Есть сохранённые практики:** карусель — одно сообщение, листание стрелками **⬅️ / ➡️** и счётчик **«N / M»**. На карточке:

- заголовок из каталога (`title`);
- время, сложность, канал;
- ссылка на YouTube;
- кнопки **«🧡 Убрать»** / **«🧡 В избранное»** и **«✅ Я сделал!»**.

Порядок в списке: **новые сверху** (по дате добавления).

### «✅ Я сделал!» и кнопка избранного


| Ситуация                       | Поведение                                                                          |
| ------------------------------ | ---------------------------------------------------------------------------------- |
| Нажали «✅ Я сделал!»           | Кнопка «Я сделал!» **исчезает**; «🧡 В избранное» / «🧡 Убрать» **остаётся**       |
| Пришла новая практика          | На **предыдущем** сообщении снимается только «Я сделал!»; избранное **остаётся**   |
| Отметка из карусели избранного | Считается в общий прогресс (streak, счётчик, напоминания) — как для других практик |




### Вне текущей версии

- фильтр «случайная из избранного» в By mood;
- избранное для бонусных практик;
- отдельный пункт в `/help` про избранное.



## 🎮 Команды бота



### Команды для пользователей

- `/start` - запускает единый онбординг: знакомство, соглашение и необязательная настройка расписания.
- `/help` - отвечает на частые вопросы и показывает, куда написать по ошибкам, идеям и общению.
- `/progress` - показывает прогресс выполненных практик, сравнение с другими; в режиме challenge — ещё строку `Прогресс в челлендже: N/28`. Сброс обнуляет общий прогресс, серию и, во время челленджа, результат `N/28`; перед сбросом бот запрашивает подтверждение.
- `/favorite` - **Избранное 🧡**: карусель сохранённых практик; добавление — кнопкой «🧡 В избранное» под практикой (см. раздел [Избранное](#-избранное)).
- `/suggest` - предложить свою практику с YouTube: бот просит ссылку и необязательный комментарий одним сообщением.
- `/donate` - способы поддержать проект: перевод на карту или Telegram Stars.
- `/change_mode` - устаревший совместимый вход; запускает тот же сценарий, что и `/start`.
- `/challenge` - запасной ручной вход в текущий поток (id практики из `CHALLENGE_START_PRACTICE_ID`; доступна, пока поток настроен; не в меню бота).
- `/challenge_off` - досрочный выход из челленджа: результат N/28 и предложение продолжить обычное расписание.



### Служебные команды (в основном для разработки/тестов)

- `/test` - отправляет тестовую практику сразу, чтобы проверить работу рассылки.
- `/myid` - показывает техническую информацию пользователя (`user_id` и `chat_id`) для отладки.



### Админ-команды (доступны только администратору)

- `/commands` - памятка: список всех команд бота (пользовательские, служебные и админские).
- `/secret` - запускает массовую рассылку всем пользователям (текст или фото с подписью).
- `/secret_delete` - удаляет последнюю массовую рассылку у пользователей.
- `/secret_edit` - редактирует текст/подпись последней массовой рассылки.
- `/flow_add` - массовая запись в поток: следующим сообщением список `@ник` / `user_id` по одному на строку; каждому — приветствие и выбор времени.
- `/challenge_summary_preview` - отправляет сводку челленджа в групповой чат **сразу**, без ожидания 10:10. Не меняет флаги и **не** запускает автозавершение.
- `/challenge_final_resend` - разово пересчитывает исправленные логи и повторно отправляет финал потока 24.08.2026 для зафиксированного состава участников; не меняет режимы и флаги, не отправляет личные сообщения.
- `/challenge_summary_reset` - сбрасывает состояние сводок и автозавершения (`system_state`) для нового потока.
- `/challenge_schedule_preview` - превью воскресного расписания в группу.

### Подписка: уведомления тестового режима

Правила и отправка реализованы в `app/subscription/jobs.py` для пользователей,
явно включённых в тестовый режим. Обычное расписание ниже сохраняется для
рабочей версии. Все времена — **Europe/Moscow**. Здесь `E` — дата перехода
в бесплатный режим в 00:00, следующий день после последнего дня доступа.

| Сценарий | Условие | Когда | Сообщение |
|---|---|---|---|
| Проба: осталось 3 дня | Нет заранее купленной подписки | E − 3 дня, 13:00 | Пробный период закончится через 3 дня |
| Проба: последний день | Нет заранее купленной подписки | E − 1 день, 19:00 | Сегодня последний день пробного периода |
| Проба завершена | По актуальным данным нет оплаченного доступа | E, 08:00 | Пробный период завершён |
| Возвращение после пробы | Бесплатный режим, нет покупки после пробы | E + 7 дней, 10:00, однократно | Избранное / расписание / подборы / универсальный вариант |
| Подписка: осталось 3 дня | До актуальной границы доступа три календарных дня | E − 3 дня, 13:00 | Подписка закончится через 3 дня |
| Подписка: последний день | Последний день актуального оплаченного периода | E − 1 день, 19:00 | Сегодня последний день подписки |
| Подписка завершена | Актуальный оплаченный период истёк | E, 08:00 | Подписка кончилась |

Для участника активного челленджа окончание платной подписки, пробы или
подарочного периода не выключает расписание потока. Во всех трёх случаях
используется универсальная серия сообщений «Полный доступ». Подборы, фильтры
и избранное переходят в бесплатный режим. Обычное напоминание через семь дней
после пробы во время активного челленджа не отправляется.

Перед отправкой повторно проверяются даты и доступ. Для одного пользователя
и окончания периода каждый вид напоминания отправляется однократно;
после продления старые напоминания не отправляются. Завершение пробы
при заранее купленной подписке **не сопровождается утренним уведомлением**.
«Оплата принята» отправляется после подтверждения и сохранения покупки,
независимо от календарных напоминаний.
Утреннее сообщение об окончании доступа включает клавиатуру бесплатного режима;
кнопка «Посмотреть тарифы» отправляется отдельным коротким сообщением, поскольку
Telegram не поддерживает два вида клавиатуры у одного сообщения. Для каждого
сообщения ведётся отдельная отметка доставки. После покупки из бесплатного
режима и отправки подтверждения оплаты бот однократно предлагает вернуть
сохранённое расписание. Кнопки «Да» и «Не сейчас» привязаны к конкретному
периоду подписки; без сохранённого времени «Да» открывает двухшаговую настройку.

### Подписки: изолированное тестирование

Новый режим по умолчанию выключен. Для проверки пробного и бесплатного
режимов в тестовом боте нужны `SUBSCRIPTION_TEST_ENABLED=true`,
`ENV_FILE=test/.env.test` и `SUBSCRIPTION_TEST_DATABASE=yogadaily_test`.
Режим действует для всех пользователей отдельного тестового бота;
`SUBSCRIPTION_TEST_USERS` необязателен и ограничивает тест конкретными ID.
Первое прохождение шага подписки в онбординге тестового бота также создаёт
15-минутную пробу; повторный `/start` её не обновляет.
ЮKassa для пробного и бесплатного режимов не требуется. Если
`SUBSCRIPTION_MINIAPP_URL` пуст, кнопки «Посмотреть тарифы» тестового бота
открывают постоянный предпросмотр Mini App; платежи в нём не создаются,
даже если тестовые реквизиты ЮKassa уже указаны. Значения секретов сюда не
записывать.
Для уже зарегистрированного пользователя тестового бота команда
`/subscription_test` показывает кнопку «Запустить тест» и запускает
ускоренную пробу на 15 минут без повторного онбординга и сброса сохранённых
данных. Через 10 минут приходит уведомление с текстом «через 3 дня», через
14 минут — «последний день», через 15 минут бот переводит пользователя
в бесплатный режим и присылает сообщение об окончании с новой клавиатурой.
Ещё через 2 минуты приходит напоминание после пробы. Фоновая проверка
уведомлений проходит каждые 10 секунд. Московский часовой пояс сохраняется;
календарные сроки и время сообщений рабочей версии не меняются.
Команду можно повторить для нового прогона в тестовом боте, если у аккаунта
нет оплаченного периода или незавершённого платёжного заказа. Повторный
`/start` по-прежнему не выдаёт новую пробу.
Миграция `data/migrations/20261013_subscriptions.sql` применена к локальной
`yogadaily_test` 14 октября 2026 года; автоматически она не выполняется.
Пользователи вне списка и без записи подписки сохраняют
существующее поведение.

Подготовлены обработчики доступа, начала пробы, меню и закрепления практики
дня; фоновая задача синхронизирует истечение доступа. Подготовлены интерфейс
и WSGI-сервер Mini App: тарифы, email, оферта, создание/проверка платежей
с подписанной сессией Telegram. В тестовом режиме задача `subscription_test_payments`
раз в минуту сверяет незавершённые заказы и доставляет «Оплата принята» после
сохранения доступа. Отдельная задача каждые 10 секунд проверяет напоминания
о сроках и предложение восстановить расписание. Модули `app/payments/` содержат
создание и проверку тестового платежа и атомарную выдачу доступа; создание
платежа предварительно проверяет тестовый признак магазина через API.
В текущем адаптере нет формирования/отправки чеков НПД.

Для фоновой сверки предусмотрены отдельные переменные
`SUBSCRIPTION_YOOKASSA_TEST_SHOP_ID` и `SUBSCRIPTION_YOOKASSA_TEST_SECRET_KEY`.
Обе задаются вместе; файлы окружения в рамках реализации не изменялись.
Для проверки покупки обязателен публичный HTTPS-адрес платёжного Mini App
в `SUBSCRIPTION_MINIAPP_URL`. Без него бот открывает только предпросмотр
тарифов и позволяет тестировать пробу, бесплатный доступ, меню и напоминания.
Без них задача может доставлять уже подтверждённые через Mini App покупки,
но не обращается к ЮKassa. Работа ограничена списком тестировщиков.
Один сбой провайдера не блокирует доставку ранее подтверждённых покупок.
Ошибка Telegram оставляет сообщение в очереди; выдача доступа не повторяется.
Между процессами отправка защищена блокировкой PostgreSQL и журналом событий.
При неоднозначном сетевом сбое после принятия сообщения Telegram возможен
повтор текста: атомарной транзакции между Telegram и нашей БД нет.

Предпросмотр интерфейса без базы и платежей:

```bash
PYTHONDONTWRITEBYTECODE=1 ./venv/bin/python -m app.miniapp.server --port 8765
```

Открыть `http://127.0.0.1:8765/`. Этот запуск всегда использует режим
предпросмотра: попытка создать платёж отвергается сервером. WSGI-фабрика
`MiniApp` принимает тестовые зависимости явно. Чтобы открыть именно этот
предпросмотр по кнопке тестового бота, укажи в `SUBSCRIPTION_MINIAPP_URL`
публичный HTTPS-адрес, ведущий на локальный порт 8765. На странице будут
тарифы и поля, но кнопка оплаты останется отключённой; магазин ЮKassa не нужен.

Постоянный предпросмотр размещён в отдельном тестовом проекте Railway
`YogaDailyBot-MiniApp-Test`, сервис `MiniApp-Preview`:
`https://miniapp-preview-production-4b53.up.railway.app/`.
Он не меняет работающий production-сервис бота. Для загрузки использована
минимальная сборка из файлов Mini App и тарифов без базы, токенов и платёжных
ключей. Команда запуска веб-сервиса:

```sh
/bin/sh -c "exec gunicorn --workers 2 --bind 0.0.0.0:${PORT:-8080} 'app.miniapp.server:create_preview_app()'"
```

Если `SUBSCRIPTION_MINIAPP_URL` не задан, тестовый бот автоматически открывает
этот адрес кнопкой «Посмотреть тарифы». Старые сообщения с кнопками сохраняют
прежний URL. Фабрика отдаёт страницу и тарифы,
но отклоняет любые запросы на оплату; ей не нужны ключи ЮKassa, токен бота
или доступ к базе данных. Адрес Railway остаётся за веб-сервисом при его
обновлениях. Переход к реальной оплате позже потребует отдельной настройки
проверки Telegram `initData`, хранилища и платёжного провайдера, а не только
замены адреса в кнопке. Локальный тестовый бот доступен, пока запущен на
компьютере, независимо от доступности страницы на Railway.

После подготовки отдельной
тестовой БД, настроек из `test/env.test.example` и HTTPS-адреса Mini App
можно запустить тестовый HTTP-сервер командой
`ENV_FILE=test/.env.test ./venv/bin/python -B -m app.miniapp.server --test --port 8765`.
Он слушает только `127.0.0.1`; для Telegram нужен отдельный HTTPS-адрес,
который перенаправляет запросы на этот локальный порт. Перед запуском сервер
проверяет имя тестовой БД и статус `test=true` магазина ЮKassa. Тестовая оплата
подключена 15 октября через тот же Railway Mini App с параметром `?test=1`.
Возобновление незавершённой оплаты
использует прежний заказ, даже при открытии другого окна. Неизвестный исход
создания старше 23 часов не повторяется автоматически — нужна отдельная сверка.

Развёрнут режим общего адреса Railway для предпросмотра и локальной тестовой
оплаты. Обычная ссылка и `/api/*` сохраняют предпросмотр;
тестовый бот использует тот же адрес с `?test=1`. В этом режиме интерфейс
обращается к `/test-api/*`, а Railway пересылает запросы на HTTPS-origin,
заданный в `MINIAPP_TEST_BACKEND_URL`. Он должен вести через временный туннель
на локальный тестовый сервер `127.0.0.1:8765`. Токен бота, ключ ЮKassa и БД
остаются локально. Параметр `test=1` только выбирает маршрут: каждый запрос
проверяется локальным сервером по подписи тестового бота. Данные production-бота
не проходят эту проверку. При недоступности туннеля обычный предпросмотр работает.
Для возврата с ЮKassa локальному серверу и тестовому боту задаётся один
`SUBSCRIPTION_MINIAPP_URL` с `?test=1`. URL туннеля после смены нужно обновить
в `MINIAPP_TEST_BACKEND_URL`; команда запуска Railway остаётся прежней.
Production-бот продолжает использовать обычную ссылку без параметра.

15 октября локальный платёжный сервер запущен на `127.0.0.1:8766`
(порт 8765 занят другим процессом). Cloudflare Tunnel недоступен в текущей
сети по QUIC и HTTP/2; временный HTTPS-туннель поднят через localhost.run.
Проверка извне: неподписанный POST `/api/session` возвращает 401.
Сервис `MiniApp-Preview` обновлён с подтверждения владельца. Проверено через
Railway: обычная сессия — 200 и `preview=true`, неверная тестовая подпись — 401,
подписанная диагностическая сессия тестового бота — 200 и `preview=false`.
Проверка сессии не создавала платёж. Тестовый бот перезапущен с URL `?test=1`;
задача `subscription_test_payments` запущена и выполняется без ошибок.
Проверка оплаты тестовой картой, выдачи доступа, сообщения и отмены ещё предстоит.
Адрес бесплатного туннеля может измениться даже при живом SSH-процессе;
при этом нужно обновить `MINIAPP_TEST_BACKEND_URL` в Railway и дождаться deploy.

Исправления тестового сценария от 15 октября:
команда «Получить практику» в бесплатном режиме отправляет текст
«Разверни кнопки клавиатуры, чтобы выбрать практику.» с бесплатной клавиатурой,
без видео; в платном режиме сохраняется обучающее видео с полной клавиатурой. Сообщение
«Оплата принята» возвращает полную клавиатуру. При отсутствии сохранённого
расписания предложение после покупки использует текст онбординга и по «Да»
сразу открывает общий экран ввода времени без промежуточного предложения.
Тексты окончания доступа находятся в `app/subscription/messages.py`:
`paid_expired()`, `trial_expired()` и `TARIFF_PROMPT` для отдельной кнопки тарифов.
При подтверждённой отмене платежа ошибка показывается в Mini App,
отдельное сообщение в чат не отправляется, как и предусмотрено спецификацией.
Убран символ с экрана результата, кнопка возврата в бот стала основной
оранжевой. Изменения опубликованы в MiniApp-Preview с подтверждения владельца;
deploy успешен, публичные HTML/CSS проверены (HTTP 200).

Локальные проверки без базы и сетевых запросов:

В повторном онбординге после использованной пробы успешная покупка
продолжает сценарий к предложению расписания после доставки подтверждения.
Подтверждённая отмена оставляет шаг подписки и кнопки повторной покупки или
«Продолжить бесплатно», однократно сообщая об отмене в боте. Старые заказы
до входа в этот шаг не учитываются. После бесплатного завершения используются
отдельный текст `COMPLETE_FREE` и клавиатура «Практика дня» / «🔒 Подобрать практику».
Название кнопки заменено в обработчиках, текстах, тестах и спецификации.
Для тестирования оплата в повторном онбординге открывается inline-кнопкой
«Посмотреть тарифы» в отдельном сообщении; Reply-клавиатура содержит только
«Продолжить бесплатно». Прямое открытие из Reply Web App не используется,
поскольку Telegram не передаёт при нём `initData`. После окончательной отмены
в онбординге также повторно отправляется inline-кнопка тарифов.

После сохранения подтверждённой покупки платёжный сервер посылает PostgreSQL
`NOTIFY subscription_payment_ready` с ID тестировщика. Отдельное соединение
тестового бота слушает канал через `LISTEN` и запускает тот же обработчик
проверки заказов и доставки «Оплата принята». После доставки продолжается
онбординг или предлагается восстановление/настройка расписания. Сигнал сам
по себе не выдаёт доступ: обработчик читает сохранённые заказы и использует
прежние блокировки и журнал уведомлений. Минутная сверка остаётся резервной.
Ошибка сигнала после сохранения покупки не превращает успешную оплату в ошибку.
При потере соединения слушатель переподключается; при остановке бота закрывается.
Подключение ограничено локальной `yogadaily_test`, миграция БД не требуется.

Для ручной проверки окончания оплаченной подписки предусмотрены локальные
`SUBSCRIPTION_TEST_PAID_EXPIRY_USER` и `SUBSCRIPTION_TEST_PAID_EXPIRY_END`
(ISO-время с часовым поясом). Они читаются только при включении изолированного
тестового режима. В тестовой БД `paid_ends_at` выбранного пользователя должен
точно совпадать с указанным временем. За 10 минут до него приходит текст
«через 3 дня», за 5 минут — «последний день», доступ заканчивается в указанное
время, через минуту приходит сообщение об окончании. Тексты остаются обычными,
меняется только время отправки. После изменения срока покупкой ускорение
отключается автоматически. История заказов и журнал уведомлений не очищаются.
После прогона переменные можно убрать и перезапустить тестового бота.

```bash
PYTHONDONTWRITEBYTECODE=1 ./venv/bin/python -m unittest discover -s tests -p 'test_subscription_*.py'
```

## 🤝 Разработка



### Структура проекта

```
YogaDailyBot/
├── app/
│   ├── by_mood/       # By mood подбор практик
│   ├── challenge/     # Календарный поток
│   │   ├── cohort.py          # дата старта, день потока, константы 10:10 / вс 20:00
│   │   ├── jobs.py            # регистрация фоновых задач
│   │   ├── summary/           # утренние сводки (job + texts + preview/reset)
│   │   ├── week_schedule/     # воскресное расписание
│   │   ├── flow/              # /flow_add, старт, выход, /challenge, /challenge_off
│   │   └── запуск-нового-потока-челленджа.md
│   ├── daily/         # Daily/Challenge: пауза, время, советы, «Ещё практики»
│   ├── handlers/      # Обработчики команд и кнопок (в т.ч. favorites, done, progress)
│   ├── schedule/      # Планировщик Daily/Challenge-рассылки практик
│   ├── main.py        # Entrypoint
│   ├── keyboards.py   # Клавиатуры
│   ├── practice_markup.py  # Снятие «Я сделал!» с сохранением кнопки избранного
│   └── config.py      # Конфигурация из env
├── data/
│   ├── db.py          # Основной модуль БД
│   └── postgres_db.py # PostgreSQL функции и миграции
├── теория/            # Спеки (challenge-cohort-spec, favorites-spec, …)
├── test/              # Локальный тестовый запуск (run_test.sh, .env.test)
├── scripts/           # Вспомогательные скрипты (напр. чистка сообщений по дате)
├── Dockerfile         # Railway production build
└── requirements.txt   # Python зависимости
```



### Добавление новых функций

1. Создайте обработчик в `app/handlers/`
2. Добавьте команду в `app/main.py`
3. При необходимости обновите базу данных
4. Протестируйте функциональность
