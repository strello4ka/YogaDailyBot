# Челлендж по дате потока (спецификация на следующий запуск)

Документ фиксирует договорённости из обсуждения. **Сейчас в проде** челлендж работает по **личному счётчику** `challenge_day` у каждого пользователя. **После окончания текущего потока** можно включить режим **общего календарного потока** — тогда день 1–28 одинаковый для всех, привязан к дате старта, а не к тому, когда человек нажал `/challenge`.

---

## Зачем менять

| Сейчас | Проблема | После внедрения |
|--------|----------|-----------------|
| День челленджа = сколько практик **уже получил этот человек** | Опоздавший в понедельник получает «день 1» только во вторник; сводка в группе смотрит на `MAX(challenge_day)` — «день группы» и день человека расходятся | День потока = **календарь**: понедельник старта = день 1 для всех |
| `/challenge 54` каждый вводит id вручную | Риск разных `challenge_start_id` | Id практики задаётся **один раз** в настройках потока |
| Каждый сам жмёт `/challenge` и вводит id | Нет единого старта потока; нельзя «подтянуть» список из группы (Telegram не отдаёт боту полный список участников) | **Админ-массовая запись** уже известных боту пользователей → бот сам проставляет параметры челленджа и шлёт приветствие + выбор времени |
| Выход только по `/challenge_off` | После финала каждый должен сам выйти | На **день 29** бот сам пишет всем с `bot_mode = challenge` итог + выбор режима |
| «Мой прогресс» / «Я сделал» — только общий счётчик | В челлендже не видно N/28 | В режиме challenge — доп. строка прогресса потока |

**Важно:** не включать cohort-режим **посреди** идущего потока — только после финала + `/challenge_summary_reset` и с правильной `CHALLENGE_START_DATE`.

## Что уже сделано в проде (не откатывать)

Эти части **уже работают** без привязки к дате и останутся при включении потока:

- Утренняя сводка **10:10 МСК** в `CHALLENGE_GROUP_CHAT_ID`
- Промежуточные итоги в дни **8, 15, 22** (понедельники), без блока «за вчера» — N/M за все прошедшие дни + «Вы прекрасны! Продолжайте!»
- Расписание на неделю **воскресенье 20:00 МСК** (формат с 🌀, жирный день + минуты, заголовок, канал)
- Правила зачёта «Я сделал» (см. раздел ниже)
- Админ: `/challenge_summary_preview`, `/challenge_summary_reset`, `/challenge_schedule_preview`
- Запасной `/challenge_off` для **досрочного** выхода (сохранить)

## Переменные окружения (новый поток)

Задать в Railway **перед** стартом:

| Переменная | Пример | Назначение |
|------------|--------|------------|
| `CHALLENGE_START_DATE` | `2026-07-07` | Понедельник старта потока (YYYY-MM-DD, МСК) |
| `CHALLENGE_START_PRACTICE_ID` | `54` | С какой практики в базе идёт день 1 (всем один id) |
| `CHALLENGE_GROUP_CHAT_ID` | `-100…` | Группа для сводок и расписания |

Если `CHALLENGE_START_DATE` **пустая** — бот остаётся на **старой** логике (`challenge_day` у пользователя).

## Календарь потока (бизнес-правила)

Пример: старт **понедельник 7 июля 2026**, практика **54**.

### Подготовка (перед стартом)

- Админ выставляет env (дата, id практики, группа).
- `/challenge_summary_reset` — если до этого был другой поток.
- В группе можно анонсировать: «Старт в понедельник, в воскресенье — расписание».

### Запись участников (админ-массовая)

**Источник участников — база бота**, не список участников Telegram-группы.

Telegram **не отдаёт** боту полный список участников обычной группы. Бот может писать в личку только тем, кто уже открыл диалог (/start). Поэтому запись = админ указывает уже известных боту пользователей (по `user_id` или `@nickname` из таблицы `users`).

| Шаг | Кто | Что происходит |
|-----|-----|----------------|
| 1 | Админ | `/flow_add`, затем следующим сообщением список (`@ник` или `user_id` по строке); параметры потока из env |
| 2 | Бот | В БД проставляет параметры участника челленджа (`challenge_start_id`, старт сценария setup и т.п.) |
| 3 | Бот | В личку каждому шлёт **то же приветствие, что сейчас при старте челленджа** (`CHALLENGE_WELCOME_TEXT`) + выбор времени рассылки |
| 4 | Участник | Выбирает время → `complete_user_challenge_setup` → `bot_mode = challenge`, рассылка с `first_daily_send_date` |

Дополнительно:

- Массовую запись удобно делать до старта; опоздавших можно дописать админом и позже (`/flow_add` не ограничен календарным окном).
- **Опоздавший в понедельник** (даже днём) = всё равно **день потока по календарю**; первая практика — **сегодня**: в выбранное время, а если оно уже прошло — сразу после сохранения времени.
- Пользователь **без диалога с ботом** в список массовой записи не попадает (сначала /start).
- Самостоятельная запись пользователем **не основной сценарий**. Запасной путь: `/challenge` (без id — практика из env), пока поток настроен в env; в меню бота не показывается. Отдельного календарного окна записи нет.
- **Досрочный выход:** `/challenge_off` остаётся (см. раздел «Выход из челленджа»).

### Воскресенье перед стартом

- **20:00 МСК** — расписание на **дни 1–7** (первая неделя). Достаточно настроенного потока и `CHALLENGE_GROUP_CHAT_ID`; активные участники **не обязательны**.
- Дни подписываются **реальными днями недели** (Пн, Вт, … от даты старта), не «День 1».

### Понедельник – день 28

- Ежедневные практики по расписанию пользователя.
- **10:10** — сводки (см. таблицу типов).
- Каждое **воскресенье 20:00** — расписание на следующую неделю (дни 8–14, 15–21, 22–28).

### День 29: финал потока (группа + личные сообщения)

Триггер — **календарный день 29** от `CHALLENGE_START_DATE` (тот же, что и финальная сводка в группе). Источник истины — дата в env; «день 29» — имя этой календарной точки.

В **10:10 МСК** (или сразу после успешной финальной сводки):

1. **В группе** — финальная сводка + рейтинг (как сейчас); флаг `challenge_summary_stopped`.
2. **В личку всем** с `bot_mode = challenge` (включая на паузе) — автозавершение (см. ниже).

Новый поток: новая дата в env + `/challenge_summary_reset`.

## Выход из челленджа

### Автозавершение на день 29 (основной сценарий)

Бот **сам** (без нажатия кнопки) для **всех** пользователей с `bot_mode = challenge`:

1. Считает личный результат потока (N из 28 засчитанных дней — та же логика, что для финального рейтинга).
2. Пишет сообщение на базе текущего текста `/challenge_off`, **с результатом**, например:
   - «Режим челленджа завершен ✔️»
   - «Твой результат: *N/28* дней» (формулировку можно уточнить при реализации)
   - «Какой бы ни был твой результат, ты супер! … прогресс будет сохранен.»
3. Переводит в `bot_mode = pending` (как сейчас `clear_user_challenge`: сброс `challenge_start_id` / `challenge_day` режима, рассылка выключена).
4. Шлёт сообщение с **выбором режима** (Daily / By mood и т.д. — как после `/challenge_off`).

Если человек **не выбрал новый режим** — остаётся `pending`, практики не идут; **напоминания о выборе режима такие же, как при онбординге** (сценарий выбора режима после /start).

### Досрочный выход: `/challenge_off`

- Команда **сохраняется**.
- Поведение как сейчас: выход в `pending` + текст завершения + выбор режима.
- В текст досрочного выхода **результат N/28 можно не добавлять** (или добавить по желанию при реализации — не блокер).
- Напоминания при отсутствии выбора режима — те же, что при онбординге.

## Сводки в группе (итоговая логика)

«День потока» для типа сообщения = **календарный день 1–28** от `CHALLENGE_START_DATE`, а не `MAX(challenge_day)` пользователей.

| День потока | Календарь (если старт в пн) | Сообщение в 10:10 |
|-------------|----------------------------|-------------------|
| 1–6, 7, 9–14, … | будни/вс | **Итоги за вчера** (кто выполнил / не выполнил) |
| **8, 15, 22** | **понедельники** | Только **промежуточные итоги** N/M (весь челлендж на сегодня) + «Вы прекрасны! Продолжайте!» (без «за вчера») |
| **28** | воскресенье | **Итоги за вчера** (последний день практик) |
| **29** | понедельник | **Финал** + рейтинг (за все 28 дней) **и** личные сообщения автозавершения всем с `bot_mode = challenge` |
| > 29 | — | Ничего, пока не reset |

Промежуточный N/M — **M** = прошедшие дни **без сегодняшнего** (сводка на 15-й день: «10/14»), с учётом замен (см. зачёт).

## Зачёт «✅ Я сделал» (уже в коде, сохранить)

### Ежедневная сводка «вчера»

Участник в списке **выполнили**, если:

- нажал «Я сделал» **вчера** (МСК) на **любой** практике (челлендж, «Ещё практики»), **или**
- отметил практику челленджа, **отправленную вчера** (в т.ч. утром следующего дня, пока сегодняшняя ещё не пришла).

### При нажатии кнопки (режим challenge)

1. Отмечается нажатая практика (последняя незакрытая в логе).
2. Дополнительно:
   - все **незакрытые** практики челленджа, **отправленные сегодня** (замена через «Ещё практики»);
   - если **сегодняшняя из расписания ещё не приходила** — закрывается **последняя незакрытая** практика челленджа (вчерашняя).

### Промежуточные итоги и финал

День засчитан, если отмечена практика из расписания **или** в **тот же календарный день** (МСК) нажали «Я сделал» на любой другой практике бота.

Реализация: `mark_practice_completed_today`, `get_yesterday_completed_challenge_user_ids`, `get_challenge_completed_in_last_n_days` в `data/postgres_db.py`.

## Прогресс в режиме челленджа (личное)

Сейчас «✅ Я сделал» и «Мой прогресс» показывают только **общий** прогресс (всего практик + серия дней).

### Новое поведение

Пока `bot_mode = challenge`, дополнительно показывать строку прогресса **именно в челлендже**, например:

`Прогресс в челлендже: *N/28*`

| Где | Показывать строку челленджа? |
|-----|------------------------------|
| «✅ Я сделал» при `bot_mode = challenge` | Да |
| «Мой прогресс» / `/progress` при `bot_mode = challenge` | Да |
| В других режимах (daily, by_mood, pending) | **Нет** |
| После автозавершения / `/challenge_off` | **Нет** (режим уже не challenge) |

### Сброс прогресса

- Кнопка «Сбросить прогресс» сбрасывает **общий** трекер (всего практик, серия и т.п.), как сейчас.
- **Счётчик / зачёт дней челленджа не сбрасывать** — челлендж = отдельная метрика потока (логи `practice_logs` / зачёт для сводок и N/28).

## Технический план внедрения (для разработки)

### 1. Модуль `app/challenge/cohort.py`

Центр логики потока. Основные функции:

| Функция | Назначение |
|---------|------------|
| `get_challenge_start_date()` | Парсит `CHALLENGE_START_DATE` |
| `get_challenge_start_practice_id()` | Парсит `CHALLENGE_START_PRACTICE_ID` |
| `is_cohort_configured()` | Обе env заданы |
| `get_cohort_challenge_day(for_date?)` | День 0 до старта; 1 в понедельник старта; … 28; 29 = финал |
| `get_first_send_date_for_enrollment(for_date?)` | До старта — день старта; в день старта и позже — сегодня |
| `get_upcoming_week_day_range(cohort_day)` | Для расписания вс 20:00: следующие 7 дней потока |
| `enrollment_closed_message()` | Текст пользователю, если поток не настроен |

Формула дня потока:

```
если дата < CHALLENGE_START_DATE → 0
иначе → (дата − CHALLENGE_START_DATE).days + 1
```

### 2. `app/config.py`

Добавить `CHALLENGE_START_DATE`, `CHALLENGE_START_PRACTICE_ID`.

### 3. `data/postgres_db.py`

- `get_group_challenge_day()` — если cohort: `get_cohort_challenge_day()`, иначе `MAX(challenge_day)`.
- `complete_user_challenge_setup()` — `first_daily_send_date` из `get_first_send_date_for_enrollment()`.
- `set_user_challenge_day()` — синхронизация `challenge_day` с днём потока при рассылке.
- Рассылка в **день старта** для новых участников (правка `get_users_pending_for_today` при необходимости).
- Хелперы для **массовой записи**: резолв `@nickname` / `user_id` → пользователь в `users`; пакетный `start_user_challenge_setup` с id из env.
- Убедиться, что `reset_user_progress` **не** трогает зачёт дней челленджа (метрика потока).

### 4. `app/schedule/scheduler.py`

- Номер практики челленджа = **день потока**, не `increment_challenge_day` вслепую.
- После отправки: `challenge_day` пользователя = текущий `cohort_day`.
- Практика: `get_yoga_practice_by_challenge_order(CHALLENGE_START_PRACTICE_ID, cohort_day)`.

### 5. Старт / финал / запасные команды (`flow/`)

- `flow/flow_add_command.py` — `/flow_add` (основная запись).
- `flow/start_flow.py` — приветствие и выбор времени.
- `flow/exit_flow.py` + `flow/exit_job.py` — завершение и автовыход день 29.
- `flow/hand_commands.py` — запасные `/challenge` и `/challenge_off`.

### 6. Сводки и расписание

- `summary/` — утренние сводки; `week_schedule/` — воскресное расписание.
- Константы дней/часов — в `cohort.py`.

### 7. `app/handlers/progress.py` + `app/handlers/done.py`

- При `bot_mode = challenge` добавлять строку `Прогресс в челлендже: N/28`.
- В других режимах строку не показывать.
- Сброс общего прогресса не влияет на зачёт челленджа.

### 8. `test/env.test.example`

Примеры `CHALLENGE_START_DATE` и `CHALLENGE_START_PRACTICE_ID`.

## Риски и ограничения

- **Не деплоить cohort mid-challenge** — у участников разъедутся дни и сводки.
- Telegram-группа и база **не связаны**: бот **не может** сам выгрузить всех участников чата. В челлендж и сводку попадают только те, кто в `users` и записан админом (или запасным сценарием) с `bot_mode = challenge`.
- Личные сообщения только пользователям с открытым диалогом с ботом.
- Ретро-зачёт после сводки: правка `completed_at` в `practice_logs` вручную; отдельной админ-команды нет.
- Уже отправленные сообщения в группе **не пересчитываются**.
- Автозавершение на день 29 затронет **всех** с `bot_mode = challenge` — перед новым потоком не должно остаться «чужих» активных challenge-режимов от прошлого запуска.
