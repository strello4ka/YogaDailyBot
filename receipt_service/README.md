# Автоматизация чеков YogaDailyBot

Отдельный сервис Railway. Он читает успешные платежи YogaDailyBot напрямую из
ЮKassa, регистрирует доход через неофициальный API «Мой налог» и отправляет
покупателю ссылку на чек по email. Доступ к базе YogaDailyBot ему не нужен.

`RECEIPT_ADMIN_EMAIL` включает однократные уведомления о платежах, которые требуют
ручной проверки. Отметки о доставленных письмах в Apps Script автоматически
удаляются через 30 дней.

## Безопасный запуск

1. Создать отдельный Railway Service из этого репозитория и выбрать
   `receipt_service/Dockerfile`.
2. Подключить Railway Volume к `/data`: SQLite содержит очередь и защищает от
   повторных чеков после перезапуска.
3. Перенести переменные из `receipt_service/.env.example` в Railway Variables
   именно сервиса чеков, не бота или Mini App.
4. Сначала оставить `MYNALOG_WRITES_ENABLED=false` и
   `RECEIPT_EMAIL_ENABLED=false`. Сервис будет только собирать подходящие платежи.
5. После проверки одного тестового сценария отдельно включить запись в «Мой
   налог», затем email.

`MYNALOG_AUTH_CHECK_ON_START=true` проверяет refresh token при запуске, но не
создаёт чеки. Успешная проверка фиксируется только строкой в логах; значения
токенов в лог не выводятся.

Однократный рабочий цикл (не универсальный dry-run):

```bash
python -m receipt_service.main --once
```

При `MYNALOG_WRITES_ENABLED=false` и `RECEIPT_EMAIL_ENABLED=false` отключены
обычная регистрация новых чеков и письма покупателям, **но не все внешние действия**:
настроенные `RECEIPT_BACKFILL_*` принудительно включают создание чека и email;
`MYNALOG_AUTH_CHECK_ON_START=true` проверяет авторизацию; задачи `unknown`
сверяются с «Моим налогом», а `RECEIPT_ADMIN_EMAIL` разрешает письма владельцу.
Не использовать `--once` как проверку «без побочных эффектов». Перед ограниченным
опросом проверить отсутствие backfill, отключить проверку авторизации и письма
владельцу; существующая очередь `unknown` всё равно может вызвать чтение «Моего налога».
Локальный запуск не загружает `.env` автоматически: переменные должны быть
уже заданы окружением процесса.
Локальное состояние очереди без сетевых запросов:

```bash
python -m receipt_service.main --status
```

Сервис обрабатывает только реальные успешные платежи с меткой
`receipt_service=yoga_daily_v1`. Email хранится в собственной очереди только до
успешной отправки, затем поле очищается.

Платежи выбираются по времени списания (`captured_at`), а не создания заказа:
позднее завершение оплаты не теряется. Сохранённая контрольная точка сохраняет
приоритет над стартовым окном опроса после перезапуска; повторно прочитанные
платежи не создают второй чек благодаря уникальному ID в SQLite.

Для разового переноса старого успешного платежа без метаданных можно задать
`RECEIPT_BACKFILL_PAYMENT_ID`, `RECEIPT_BACKFILL_EMAIL` и
`RECEIPT_BACKFILL_SERVICE_NAME`. Такой платёж обрабатывается один раз даже при
выключенных общих флагах; повторный запуск безопасен благодаря уникальному ID в
SQLite.

На тарифах Railway без SMTP можно использовать Google Apps Script по HTTPS:
установить `RECEIPT_EMAIL_TRANSPORT=apps_script`, `RECEIPT_APPS_SCRIPT_URL` и
`RECEIPT_APPS_SCRIPT_SECRET`. Код шлюза находится в
`receipt_service/google_apps_script/Code.gs`; секрет хранится в Script Properties,
а каждый запрос подписывается HMAC и действует пять минут.

## Важное ограничение

API «Мой налог» не является публичным стабильным API. Перед первым включением
записи нужно проверить авторизацию и создание одного согласованного чека. При
потере или некорректном ответе после POST задача переводится в `unknown`: сервис ищет уже
созданный чек и не выполняет опасный слепой повтор.
